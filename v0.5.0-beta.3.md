# NEXT System Control v0.5.0 Beta 3 — Debugger Diagnostic

Beta 3 is a diagnostic build for testing the read-only ps4debug client when
connecting to the console's detected local IPv4 address. It does not include
or load ps4debug-NG, start GoldHEN services, or grant privileges.

## Changed

- The manual debugger query targets NEXT's freshly detected console-local IPv4
  address on TCP port 744 instead of assuming that PS4 loopback (`127.0.0.1`)
  reaches the payload listener.
- The target address is obtained from NEXT's network snapshot; the client does
  not accept a user-supplied remote host.
- No connection is attempted until the user manually requests the read-only
  query.

## PS4 diagnostic result

The maintainer tested this exact package on PS4. The screen showed the
detected local address as the target, but the connection failed with
`errno 61` (connection refused) on TCP port 744. This confirms the client
attempted the detected console address; it does **not** confirm that
ps4debug-NG started or that a debugger server is listening. Use this release
as a diagnostic build, not as a claim that debugger connectivity is fixed.

## How to test

1. Install the package using the PS4 package installer and launch NEXT.
2. Open the read-only GoldHEN / PS4Debug diagnostic screen.
3. Confirm the displayed destination is the console's current local IPv4 on
   port 744, then press X once to run the manual query.
4. Record the exact status. A connection-refused result means port 744 is not
   reachable; it does not identify why the server is unavailable.

NEXT does not load or resend a payload as part of this query. It does not
attach to processes, access process memory, alter the kernel, or elevate
privileges.

## Network use

Enable SSH or FTP only when needed on a trusted local network. FTP is not
TLS-encrypted; do not expose either service to the public internet.
